# Дословно

Поиск по субтитрам каналов YouTube. Добавляете канал, и программа скачивает субтитры его последних видео (по умолчанию 200). Дальше можно искать фразу по всему, что там было сказано: каждое совпадение показывается с меткой времени и открывается в плеере с этого места.

Раньше проект был сервером на Node.js (`server.js`, в истории git — коммит 2474c00). Теперь это один бинарник на Go с вшитым интерфейсом. Старый `cache.json` новая версия не читает: каналы добавляются заново.

## Запуск

Нужен ключ YouTube Data API v3 ([Google Cloud Console → Credentials](https://console.cloud.google.com/apis/credentials)). Им ищется канал и список его видео. Сами субтитры скачиваются без ключа.

```sh
# вписать ключ в строку YOUTUBE_API_KEY= в файле .env
./tasks.sh run          # собрать и запустить: http://127.0.0.1:3000
```

Для сборки нужны Go 1.26, Node 24 и pnpm 11. Команды `tasks.sh`:

| команда | что делает |
|---|---|
| `build` | собирает интерфейс и бинарник `bin/doslovno` с вшитым интерфейсом |
| `run` | собирает и запускает, флаги передаются серверу: `./tasks.sh run -limit 100` |
| `dev` | Go в режиме `-dev` на :3000 и `ng serve` на :4200 с прокси `/api` |
| `test` | сборка, тесты Angular и Go |
| `clean` | убирает сборки |

Флаги:

| флаг | по умолчанию | что делает |
|---|---|---|
| `-addr` | `127.0.0.1:3000` | адрес сервера |
| `-data` | `~/.local/share/doslovno` | где лежат каналы и субтитры |
| `-limit` | `200` | сколько последних видео канала брать |
| `-langs` | `ru,en` | язык ручных субтитров, если у видео нет автоматических |
| `-client-version` | `20.10.38` | версия клиента Android, которой сервер представляется плееру YouTube |
| `-ytdlp` | `auto` | запасной путь через [yt-dlp](https://github.com/yt-dlp/yt-dlp): `auto` — если он есть в `PATH`, `off` — без него, или путь к программе |
| `-dev` | — | запуск без собранного интерфейса (для `ng serve`) |

Если YouTube блокирует адрес («too many requests», капча), можно пустить запросы через прокси: `HTTPS_PROXY=http://… ./bin/doslovno`.

## Интерфейс

`web/` — Angular 22 (standalone-компоненты, сигналы, без zone.js).

- Слева список каналов. У каждого видно, сколько видео с субтитрами, а во время индексации — прогресс, текущее видео и обратный отсчёт паузы, если YouTube притормозил запросы. Отсюда же можно остановить, докачать, обновить и удалить канал (удаление — со вторым подтверждением).
- В центре одно поле поиска. Клавиша `/` ставит в него курсор, запрос сохраняется в адресе (`?q=…&channel=…`). Совпадения сгруппированы по видео: превью, название, дата, число совпадений. Каждое совпадение показано со строкой до и после, искомые слова подсвечены. Видны три совпадения, остальные открывает «Ещё N».
- Справа плеер. Клик по метке времени открывает видео с этого места. Повторный клик по тому же видео только перематывает, iframe не пересоздаётся. На экранах уже 1280 px плеер всплывает карточкой внизу, уже 1024 px — панелью во всю ширину, а каналы сворачиваются над поиском.
- Темы: светлая, тёмная и «как в системе». В тёмной нет светлых плашек. Если в системе включено «уменьшить движение», анимации выключены.
- Шрифты и значки лежат в репозитории (`THIRD_PARTY.md`), в сеть интерфейс ходит только за превью видео и плеером YouTube.

## Как устроено

`server/` — Go 1.26, только стандартная библиотека.

- `internal/transcript` — скачивает субтитры по той же схеме, что python-библиотека [youtube-transcript-api](https://github.com/jdepoix/youtube-transcript-api). Сначала запрос к внутреннему API плеера YouTube от имени клиента Android, потом XML дорожки. На видео уходит 2 запроса. Если плеер ответил странно, сервер берёт страницу видео: из неё ключ innertube и cookies согласия.
  - Дорожка выбирается на языке речи. Сначала ручная на языке автоматической, затем сама автоматическая.
  - Ошибки различаются: блокировка адреса, нет субтитров, 18+, видео недоступно, нужен PO-токен.
  - Запасной путь — yt-dlp, если он установлен. Он нужен, когда YouTube требует PO-токен или ответ плеера не разобрать (так бывает после изменений на стороне YouTube). yt-dlp отдаёт только список дорожек (`-J`), саму дорожку качает тот же код. На видео уходит 5–20 с вместо секунды. При блокировке адреса запасной путь не запускается: он ходит с того же адреса и сделал бы только больше запросов.
- `internal/youtube` — клиент YouTube Data API. Понимает `@имя`, ID канала `UC…`, ссылки на канал и видео, `/user/…`. Поиск по названию стоит 100 единиц квоты из 10 000 в сутки, поэтому выполняется только по явной просьбе. Ключ уходит заголовком `X-Goog-Api-Key`, а не параметром URL.
- `internal/library` — каналы на диске, по файлу `channels/<id>.json` на канал. Папку данных держит блокировка `flock` на файле `lock`: второй сервер на той же папке не запустится, иначе два процесса переписывали бы файлы друг друга.
  - Запись атомарная: временный файл, fsync, rename. Битый файл не затирается, а откладывается в `.corrupt-<время>`.
  - Поиск идёт по всем строкам видео, склеенным в одну, поэтому находит и фразу, которую субтитры разорвали между строками. Регистр и разница «е»/«ё» не учитываются.
  - Вхождения на соседних строках (или через одну) показываются одним совпадением до 6 строк, чтобы контекст не повторялся.
- `internal/indexer` — фоновая индексация.
  - Очередь одна на всё приложение, загрузки идут по одной. Между видео пауза 1–2 с.
  - После блокировки пауза растёт: 1, 2 минуты. После трёх блокировок подряд задание останавливается на 30 минут. Этот предохранитель сохраняется в `state.json`, так что перезапуск не начинает стучаться заново.
  - Повторная индексация скачивает только то, что не удалось: временная ошибка не записывается как окончательная. «Нет субтитров» у видео моложе недели тоже не окончательно: YouTube делает автоматические субтитры не сразу, поэтому такое видео перепроверяется, но не чаще раза в 6 часов.
  - При запуске и перед каждым заданием сервер проверяет DNS. Если сеть подменяет `www.youtube.com` на `restrict.youtube.com` или `restrictmoderate.youtube.com` (так включают «Безопасный режим» публичные Wi-Fi и родительские фильтры), интерфейс об этом предупреждает: часть видео в такой сети недоступна.
- `internal/api` — HTTP API и поток изменений (SSE). Сервер принимает запросы только с локальным `Host`, отклоняет `Sec-Fetch-Site: cross-site`, а меняющие запросы — только с JSON. Так чужая страница в браузере не может управлять сервером.
- `internal/web` — раздаёт вшитую сборку интерфейса.

API:

| запрос | что делает |
|---|---|
| `GET /api/state` | каналы, их счётчики и задания |
| `GET /api/events` | то же потоком SSE при каждом изменении |
| `GET /api/search?q=&channel=` | поиск, совпадения сгруппированы по видео |
| `POST /api/resolve {query, search}` | найти канал по вводу |
| `POST /api/channels {id, limit}` | добавить канал и поставить в очередь |
| `POST /api/channels/{id}/refresh {force}` | переиндексировать (`force` снимает предохранитель) |
| `POST /api/channels/{id}/cancel {}` | остановить |
| `DELETE /api/channels/{id}` | удалить канал и его субтитры |
